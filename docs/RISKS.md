# Risks, detection, and fallback decisions

Status: planning, 2026-10-07. Priorities describe work order, not estimated probabilities. See [SETUP](SETUP.md) for commands and [VALIDATION](VALIDATION.md) for test definitions.

| Risk | Detection / gate | Mitigation / decision |
|---|---|---|
| No working native MPS/CUDA path for selected operations | M0 diagnostics then M1 full fixture forward/backward/AdamW; log dtype/device and environment | Use portable operation composition; choose a jointly available release if necessary. CPU mode is a diagnostic fallback, never evidence of mixed-GPU success. |
| Different software builds silently change semantics | Record Python, torch base release/build, OS, driver, config and state hashes | Freeze platform lock records together. Compare common base release, permit platform build suffix. Run numerical suite after upgrades. |
| Campus AP client isolation or blocked local ports | Peer TCP echo fails despite listener/local echo success; repeat on private hotspot | Use Windows-hosted or phone hotspot if client-to-client traffic works. No public port forwarding or firewall disablement. If no local link works, hardware experiment waits; design/test locally meanwhile. |
| Wi-Fi overhead dominates compute | Tensor-size sweeps, directional throughput/RTT p50/p95/p99, copy decomposition, end-to-end step time | Reduce boundary frequency with contiguous split, test b/T/K grid; accept capacity-only value. No speedup promise or internet speed-test proxy. |
| 6 GB CUDA budget exhausted including optimizer first step | Full forward/backward/AdamW peak memory, not parameter-only estimate | Smaller local partition, account for head/embedding placement; reserve workspace/headroom. Reprofile at sustained load. |
| Mac unified memory pressure / swap / OS termination | MPS allocator+driver metrics, process RSS, OS memory pressure/swap, prolonged run | Keep measured headroom and bounded CPU buffers; lower partition/batch/T. Do not raise allocator limits or disable safeguards to make capacity claims. |
| Largest layer or output logits do not fit either stage | Per-layer and full-stage profiles, vocabulary/sequence sweeps | Change model dimensions or use documented later techniques; aggregate memory does not guarantee a feasible contiguous split. |
| Initialization/checkpoint causes a transient full-state allocation | Peak host/device measurements during cold initialization, first Adam step, save and restore | Instantiate owned layers only, generate/load bounded tensors, stream optimizer tensors; no coordinator gather. Fail when estimated headroom is insufficient. |
| Gradient wrong at detached boundary | Every parameter and boundary-gradient comparison with same CPU initial state | Retain original output graph, create receiving leaf, return its normalized gradient, backward exactly once. See architecture. |
| Incorrect accumulation with padding/unequal microbatches | K=2 tests with unequal valid targets and an empty microbatch | Divide summed token loss by global step token count once; reject all-empty step before forward. |
| Partial optimizer application or lost acknowledgement | Fault injection before/during/after STEP_APPLY, STEP_APPLIED and STEP_COMMITTED | Abort entire run; restore last complete checkpoint under fresh run ID. No retry of uncertain updates or in-run rejoin. |
| Partial or corrupt checkpoint accepted | Kill during writes; alter shard hash; remove one shard | Local durable completion receipts + final complete manifest; verify all shards before any resume. Retain prior complete checkpoint. Local disk loss is outside two-machine restart guarantee. |
| Deadlock/backpressure blocks failure reporting | Fragmentation, slow-reader and stalled-large-frame tests; progress deadlines | One writer per socket, bounded queues, frame deadlines and out-of-band local cancellation; abort if incomplete frame blocks control. See protocol for exact timeouts. |
| Duplicate/stale messages update parameters twice | Duplicate command/version/sequence and delayed-run injection | State machine rejects before effects, never reconnects within run. No implicit exactly-once network guarantee. |
| Malicious peer or accidental large allocation | Wrong auth, oversized dimensions/header/payload, malformed enums | Trusted private LAN, authenticated admission, validated caps before allocation, no pickle. Plain TCP lacks confidentiality; use private hotspot or later TLS. |
| Timing hides GPU asynchrony or CPU fallback | Explicit synchronization, fallback env check, device trace sampling | Wall-clock timings with backend synchronize around isolated regions; no `.item()` inside measured kernels except recorded sync costs. Report intended host work separately. |
| Thermal throttling/power saving changes split ranking | Warmup plus at least 20-minute sustained trial with power/temperature context | Plug in both machines, prevent sleep for trial, record power mode and app load. Adaptive policy only for sustained changes, not Wi-Fi spikes. |
| Migration loses optimizer history or costs more than it saves | State hash/equivalence after migration; full measured drain/save/transfer/load/resume duration | Move params and Adam moments/counters at safe boundary, preserve global names/RNG/data state; conservative savings threshold and cooldown. Abort on uncertain migration. |
| Claimed novelty already exists | Compare SWARM, AMP, HetPipe, newer hetero/low-bandwidth systems | Frame contributions as evaluated hypotheses; maintain dated literature comparison. A missing repo feature is not novelty evidence. |
| Code reuse creates licensing obligations | Verify LICENSE at chosen immutable commit and dependency notices | No third-party code copied in this planning run. Record provenance and notices before incorporation; missing license means no code reuse pending permission. |

## Nonblocking assumptions to resolve at M0/M1

Exact OS builds, Windows NVIDIA driver, free disk, available RAM under idle/load, Mac native ARM64 interpreter, administrative ability to add a scoped firewall rule, permitted campus/hotspot policy, IP addresses, local link metrics, power modes, and common wheel installation remain unknown. The machines can be present on one private local network and each can store its own checkpoint shards; validate both assumptions.

No credentials, campus network changes, driver installs, package installs, or target-hardware experiments were performed by this planning run. Proposed benchmark budgets and expected command outputs are not observations.
