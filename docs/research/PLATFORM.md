# Platform evidence and setup decisions

Access date for every source below: **2026-10-07, Asia/Kolkata**. Evidence labels: **D** documented by the maintainer; **I** engineering inference/decision; **U** unverified on target hardware. No Windows RTX 4050 or M4 hardware execution was performed in this research run.

## Recommended compatibility candidate

**I/U:** CPython **3.13, standard GIL build**, 64-bit x86 Windows and native ARM64 macOS; **PyTorch 2.11.0** on both, CUDA 12.8 build on Windows. This is a reproducible candidate, not a claim that 2.11 is the newest release. Use the latest available security patch of Python 3.13 and record its exact version. Python 3.11 also has matching wheels, but is not the setup default. No torchvision, torchaudio, compiler, DeepSpeed, MLX, NCCL, or separate CUDA Toolkit is required for the first eager-mode model.

**D:** The official [previous-release installation page](https://pytorch.org/get-started/previous-versions/) gives 2.11.0 macOS and Windows CUDA 12.8 installation commands. The official indexes list `torch-2.11.0+cu128-cp313-cp313-win_amd64.whl` ([CUDA index](https://download.pytorch.org/whl/cu128/torch/)) and `torch-2.11.0-cp313-cp313-macosx_11_0_arm64.whl` ([CPU/macOS index](https://download.pytorch.org/whl/cpu/torch/)). The macOS wheel includes MPS despite the index name. Wheel listing is artifact evidence, not an installation or operator test. These indexes also expose cp311/cp312 builds if a later setup constraint requires a coordinated change.

**D/I:** [Apple's PyTorch page](https://developer.apple.com/metal/pytorch/) explicitly describes 2.11.0, Apple silicon, macOS 14+, and Python 3.10+. The [versioned PyTorch MPS note](https://docs.pytorch.org/docs/2.11/notes/mps.html) still contains an older 12.3 check; use Apple's stricter 14+ prerequisite and check the actual M4 OS. The wheel's `macosx_11_0` packaging tag does not establish the MPS runtime minimum. Apple's page mentions command-line tools; install them only if required by a diagnostic or dependency, since prebuilt wheels and Python sockets do not compile extensions. Do not install full Xcode for M0.

## Drivers, runtime, and operating-system constraints

**D:** [NVIDIA CUDA 12.8 release notes](https://docs.nvidia.com/cuda/archive/12.8.0/cuda-toolkit-release-notes/index.html) distinguish Windows driver 570.65 for CUDA 12.8 GA from the CUDA 12.x minor-compatibility floor 528.33. [Minor compatibility documentation](https://docs.nvidia.com/deploy/cuda-compatibility/minor-version-compatibility.html) explains feature and PTX caveats. **I/U:** prefer an appropriate supported RTX laptop driver at least 570.65, subject to actual CUDA diagnostics; do not assert every older minor-compatible driver runs every kernel. `nvidia-smi` reports installed driver and supported CUDA level; `torch.version.cuda` reports the wheel's CUDA build. Neither command establishes that a standalone Toolkit is installed. The prebuilt distribution supplies its runtime dependencies; compiling CUDA extensions would require a Toolkit, outside current scope.

**D:** [Windows FAQ](https://docs.pytorch.org/docs/2.11/notes/windows.html) describes spawn-based multiprocessing and Windows CUDA IPC restrictions. [Distributed documentation](https://docs.pytorch.org/docs/2.11/distributed.html) labels Windows distributed support prototype; its backend discussion excludes NCCL on Windows and its built-in backend matrix does not establish MPS collectives. **I:** launch coordinator and worker as separate native processes, guard process-starting entry points, use a single-process CPU data loader initially, and transfer explicit host bytes. Do not share CUDA tensors through Windows multiprocessing queues. Separate CUDA and MPS support is not evidence of mixed distributed backend support.

**D/I:** [MPS environment variables](https://docs.pytorch.org/docs/2.11/mps_environment_variables.html) document optional CPU fallback and allocator watermarks. Disable fallback for GPU claims; never disable the high-watermark memory guard to obtain an apparent capacity win. Check unsupported operations explicitly. macOS memory is shared by CPU, GPU, operating system, and applications. Host copies and coordinator buffers also count. Model/optimizer capacity must be measured after the first update, when AdamW state exists.

## Network and security evidence

**D:** [Microsoft firewall rules](https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallrule) can constrain executable, local port, profile, and peer address. [Windows mobile hotspot instructions](https://support.microsoft.com/en-us/windows/experience/connectivity-networking/use-your-windows-device-as-a-mobile-hotspot) support sharing over Wi-Fi, with hardware/policy-dependent band choices. [Python socket guidance](https://docs.python.org/3.13/howto/sockets.html) explains partial reads/writes and framing.

**I/U:** TCP 29550 is the only runtime listener, on Windows; both workers connect to it. Mac needs no inbound listener. Use a trusted private hotspot for plaintext prototype tensors, peer-IP-scoped firewall permission, and protocol challenge-response for membership. College access-point isolation can prevent local communication even when internet access works. Compare the identical listener/client test on a private hotspot before diagnosing isolation; failed ping alone is inconclusive. Do not open router forwarding or public ports. A Windows hotspot may reduce the two-wireless-client relay path, but its bandwidth benefit is unverified. A phone hotspot may itself isolate clients or require an internet uplink; test it.
