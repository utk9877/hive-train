# M2: bounded transport and fail-stop state gates

Implemented 2026-10-08: strict protocol-1 schemas, authenticated framed streams, CPU tensor encoding, fixed membership admission, serial coordinator relay, pure state gates, and a standalone transport probe. M2 tests use fake update callbacks; subsequent [M3](M3.md) adds real autograd/optimizer integration. Durable checkpoint files remain M4 work.

## Interfaces for the next implementation

| Module | Contract |
|---|---|
| `protocol.py` | `ProtocolError(code, detail)`, `Frame(metadata, payload)`, strict prefix/metadata/tensor validators; standard library only |
| `transport.py` | `SocketStream`, `Timeouts`, `server_handshake`, `client_handshake`, authenticated `Session.send/receive`, `accept_members`, state-gated `relay_one`; standard library only |
| `tensor_codec.py` | `encode_tensor(tensor, name)` → descriptor + owning bytearray; `decode_tensor(descriptor, payload, vocab_size=...)` → CPU tensor retaining the writable backing buffer; imports torch lazily |
| `state.py` | `CoordinatorState`, `WorkerState`, `apply_id_for_step(run_id, step_id)`, `accept(metadata)`, `check_timeout()`, `disconnect()`; fake update callback in tests, no model or socket ownership |
| `transport_probe.py` | Runnable `keygen`, `server`, `client` diagnostic, with directional application timings and byte-hash comparisons; no torch needed |

[PROTOCOL](PROTOCOL.md) remains the wire/state authority. Pass the inner `RUN_CONFIG.body.config` to `Session.receive(config=...)` to enforce configured tensor shapes before payload allocation. Pass actual per-stage parameter-name hashes from M1 manifests to both state constructors; omitted hashes are only useful for isolated protocol tests. Device capability assertions are supplied by M3's runtime diagnostics, not independently measured by the state gate.

Required M3 integration order:

1. Handshake/authenticate, then configure both state gates. State objects have a single compute/scheduler-thread owner. An I/O helper must not mutate them concurrently.
2. Before sending a message, build the same metadata using `transport.metadata(...)` and current `Session.send_seq`, consume it in the sender gate, then call `Session.send`. Do not emit a completion message until its local device work and synchronization succeeded.
3. Receive/authenticate using `Session.receive`, then consume its metadata in the receiving gate **before** dispatching compute. The pre-authentication metadata validator only validates structure/identity; it must not mutate any state or invoke a callback.
4. Decode authenticated tensor bytes, check token bounds and actual nonignored target counts, and transfer to the explicitly selected device. The gates verify reported counts, not payload semantics. Follow [ARCHITECTURE](ARCHITECTURE.md) for the detached leaf and resumed backward.
5. Use `relay_one(source, destination, type, config=..., state=coordinator_gate)` for a boundary relay. It consumes both authenticated receive and outgoing relay events, retaining just one payload until forwarding completes. Do not consume those events again outside this helper.
6. Pass the appropriate remaining compute/checkpoint budget as the receive wait and absolute `deadline`; default idle wait is only 30 s. Check phase deadlines between local operations too. `STATUS` cannot renew compute/checkpoint deadlines. Configure stream timeouts from the admitted run, rather than assuming defaults match every run.
7. On **any** transport, schema, tensor, state, compute or interrupt failure: stop scheduling, poison every local live gate with `disconnect()` (which raises `ProtocolError`), close all run sessions, and discard uncertain state. Never reconnect/retry an update within a run. M3 initially aborts to deterministic initialization; resuming trained state requires M4's complete checkpoint implementation.

Generate STEP_APPLY identifiers with `apply_id_for_step(run_id, step_id)`, not random UUIDs. The state gate marks APPLYING before invoking its callback, including on KeyboardInterrupt/SystemExit. A real callback must finish and synchronize the local optimizer before STEP_APPLIED; the metadata gate alone cannot prove this. Keep only bounded telemetry and active identifiers. Do not retain every received `Frame` in logs or queues.

## Memory and security boundaries

Frames have a 64 KiB metadata ceiling and 64 MiB tensor hard limit. Before authentication, bounded frame reads, metadata parsing/validation and payload allocation occur; no application dispatch or training effects. One reader and one writer per stream/session are enforced; concurrent attempts close the stream. There are no application queues. Serial relay stops reading its source while forwarding. `peak_received_payload` reports the largest allocated single received payload, **not** process RSS or total retained buffers. Socket buffers, Python metadata, simultaneous inbound/outbound storage and conversion copies are additional memory.

Encoding can hold a contiguous CPU staging tensor plus an owning bytearray; decoding retains its buffer until the tensor/device copy releases it. Finiteness/token checks allocate bounded temporary masks. Big-endian conversion incurs extra copies; big-endian target operation has not been tested. No pickle, JSON tensor arrays, CUDA IPC, distributed process groups or accelerator collectives are used.

HMAC authenticates participants and exact frame bytes; it does **not** encrypt data. Use a trusted password-protected private LAN/hotspot. No public port forwarding. One pending handshake is admitted serially; exactly two distinct workers seal training admission. Any admission failure currently fails the attempt closed; start a fresh attempt rather than repeatedly accepting an untrusted peer. The diagnostic intentionally admits only one client.

## Run the authenticated local-network probe

First complete [SETUP connectivity/firewall checks](SETUP.md). Stop the earlier echo server before reusing port **29550**. The commands below exist now but are **unverified on the target Windows/Mac**. Keep both copies of `src/` identical. No project install is needed: setting `PYTHONPATH=src` uses the checkout. The existing `.venv` from SETUP is sufficient; the probe itself has no torch dependency.

### 1. Generate a private key once

**A, ordinary PowerShell; working directory: project root.**

```powershell
Set-Location "$env:USERPROFILE\Documents\hive-train"
$env:PYTHONPATH = "src"
New-Item -ItemType Directory -Force .secrets | Out-Null
.\.venv\Scripts\python.exe -m hive_train.transport_probe keygen .secrets\m2.key
icacls .secrets\m2.key
```

Expected: `Created secret file` and a local ACL listing. The file contains exactly 32 random bytes, never printed. `FileExistsError` deliberately prevents overwriting an existing key; use a new filename for a new attempt. Check that unrelated users do not have read access; if the inherited ACL is broad, use Windows file Properties → Security or ask the machine administrator to restrict it to the owner and necessary system administrators. Do not run on a shared/untrusted machine with a broadly readable secret.

Privately transfer **that same file**, without displaying its contents, to B's project `.secrets/m2.key` using an existing trusted file-transfer method. Do not post it in chat, source control or a public/shared folder. `.secrets/` is ignored by Git if a repository is later initialized.

**B, Terminal/zsh; working directory: project root**, after the private transfer:

```zsh
cd "$HOME/Documents/hive-train"
chmod 700 .secrets
chmod 600 .secrets/m2.key
wc -c .secrets/m2.key
```

Expected: length `32`. A different length means the file was modified or transferred as text: transfer the original binary file again. `No such file` means it has not been copied to that path. Both endpoints must use the same secret for this attempt.

### 2. Start A's server, then B's client

**A, ordinary PowerShell; project root.** Enter the private Windows IPv4 selected in SETUP. The scoped firewall rule must allow this interpreter/address/port from the Mac only.

```powershell
$env:PYTHONPATH = "src"
$HIVE_BIND = Read-Host "Windows local IPv4"
.\.venv\Scripts\python.exe -m hive_train.transport_probe server --bind $HIVE_BIND --secret-file .secrets\m2.key --output artifacts\network\m2-windows.json
```

Expected: `Listening on <local address>:29550 for one diagnostic peer`. Start B within 60 s; otherwise restart both commands. For a Windows-only loopback smoke check, bind `127.0.0.1` and run `client --host 127.0.0.1` with the same PowerShell interpreter in a second terminal; save a separate output file. Loopback success is not peer connectivity.

**B, Terminal/zsh; project root**, while A is listening:

```zsh
read 'HIVE_HOST?Windows local IPv4: '
PYTHONPATH=src .venv/bin/python -m hive_train.transport_probe client --host "$HIVE_HOST" --secret-file .secrets/m2.key --output artifacts/network/m2-macos.json
```

Expected: each command exits 0 and prints a small `status: pass` JSON result with its output path. No numeric throughput is predicted. Default sizes are 1 KiB, 256 KiB, 1/4/16/64 MiB, 5 warmups + 30 measured transfers each direction, and 1,000 measured application RTTs. Allow several minutes or longer on a slow link. For an initial smoke test append **identically on both commands** `--sizes 1024 262144 --rounds 3 --warmup 1 --latency-rounds 20` and use distinct smoke output names. Return to defaults for the recorded measurement.

The Mac report contains Mac→Windows upload/ack and Windows→Mac request/download samples, hash checks, effective MiB/s and p50/p95/p99 timings. The Windows report contains application RTT samples. Timings include framing, HMAC, allocation and request/ack overhead; they are not synchronized one-way latency or GPU copy costs. The synthetic finite-FP32 payload is uncompressed. This probe reuses frame types for transport only: it intentionally does not run RUN_CONFIG or the training state machine, and its identifiers do not represent optimizer steps.

Failure returns nonzero with an error report when output storage is writable. `AUTH_FAILED`/peer EOF: compare key-file identity privately and ensure the same source version; never log the key. Connection refused: no listener or wrong IP. Timeout: inspect client isolation, scoped firewall, bind address and whether both option sets match; compare an authorized private hotspot. `Address already in use`: stop only your previous server. The transfer deadline uses a conservative 1 MiB/s bootstrap rate, not a measured guarantee. A failed or partial trial is not a throughput sample. Correct the cause and start a **new** server/client attempt; no session resumes.

Record topology, distance, power mode, OS, firewall profile, interruptions and both reports; repeat at different times. Device→CPU and CPU→device timings remain separate target checks described in [SETUP §6](SETUP.md#6-separate-accelerator-staging-costs-and-retain-m0-evidence); no staging profiler is implemented yet.
