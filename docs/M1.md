# M1: portable decoder and local split reference

Implemented: the 875,264-parameter decoder fixture, stage-only factories, named CPU initialization, local detached-boundary training, binary initialization-fixture export, and numerical tests. M1 itself has no networking. Subsequent [M2](M2.md) adds transport/state primitives and [M3](M3.md) adds real serial training. Actual M0/M1 accelerator acceptance remains pending.

## What runs today

Install the planned Python/PyTorch pair using [SETUP](SETUP.md) first. All commands below run from the project root. They use no dataset download and open no network ports. The reference keeps several **tiny** model copies and CPU snapshots for comparison; it is not the large-model memory path.

Machine A, PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m hive_train doctor --output artifacts/environment/windows.json
.\.venv\Scripts\python.exe -m hive_train verify --device cuda --steps 10 --output artifacts/validation/m1-cuda.json
.\.venv\Scripts\python.exe -m hive_train verify --device cuda --reference-device cpu --steps 10 --output artifacts/validation/m1-cuda-vs-cpu.json
```

Machine B, zsh:

```zsh
.venv/bin/python -m pip install --no-deps -e .
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m hive_train doctor --output artifacts/environment/macos.json
PYTORCH_ENABLE_MPS_FALLBACK=0 .venv/bin/python -m hive_train verify --device mps --steps 10 --output artifacts/validation/m1-mps.json
PYTORCH_ENABLE_MPS_FALLBACK=0 .venv/bin/python -m hive_train verify --device mps --reference-device cpu --steps 10 --output artifacts/validation/m1-mps-vs-cpu.json
```

Expected: unittest reports `OK`; verify reports `status: pass`, nine cases, and a fixture hash. Those are expected results, not yet observations on either target GPU. Each case is one of cuts 1/2/3 × single microbatch, unequal masked microbatches, or one entirely ignored microbatch, for ten steps each. Full reports include per-name loss/logit/boundary/gradient/parameter/update/moment errors, exact optimizer counters, data hashes, environment and source hash. Error exit status is nonzero and the requested report records the error. Unavailable devices fail without CPU fallback; `doctor` only reports availability and does not itself train or pass a GPU gate.

To isolate a failure, use `--split 2 --steps 1`; retain the report and traceback. Do not increase tolerances without investigating the first divergent operation. Running `--device cpu` exercises local CPU correctness only. NumPy is not required; a torch build may emit a missing-NumPy warning, while these operations use torch and the Python standard library exclusively.

Export the initial CPU fixture to a **new** directory (Mac zsh shown; on Windows replace the interpreter with `.\.venv\Scripts\python.exe`):

```zsh
.venv/bin/python -m hive_train fixture --output-directory artifacts/fixtures/initial-v1
```

Expected: numbered little-endian FP32 `.bin` files and `manifest.json` containing canonical names, shapes, hashes, config and initializer version. Existing directories are rejected to protect previous fixtures. This exports initialization only, not optimizer state or a resumable checkpoint. M1 comparisons load one shared CPU state in memory into all compared instances; no untrusted file loader or pickle is used.

## Frozen interfaces

- `ModelConfig` fixes dimensions; decoder operation semantics follow PROJECT_SPEC. `build_stage(config,start,end,device=...,seed=2026)` constructs only `[start,end)` blocks, prefix embeddings iff start=0, suffix norm/head iff end=L. Construction starts on meta and materializes only that stage.
- Canonical names: `token_embedding.weight`, `position_embedding.weight`; `blocks.<global_index>.norm1.{weight,bias}`, `attention.{query,key,value,output}.{weight,bias}`, `norm2.{weight,bias}`, `expand.{weight,bias}`, `contract.{weight,bias}` under each block; `final_norm.{weight,bias}`, `output_head.weight`. Embeddings and head are untied.
- `named_cpu_v1` uses UTF-8 `hive-train:init:v1:<decimal_seed>:<global_name>`, SHA-256 first eight bytes big-endian masked to 63 bits. Separate CPU generators initialize one parameter at a time without changing global CPU RNG. Golden seed vectors are tested. Fixture hashes include exact FP32 bytes and may need investigation if the underlying torch RNG implementation changes.
- `ReferenceTrainer([whole],split=k)` and `ReferenceTrainer([prefix,suffix],split=k)` own AdamW optimizers and perform serial K-microbatch steps. They normalize summed loss by total valid targets exactly once. Every stage's gradients are checked before any update. A compute/update failure poisons that local trainer; no retry or automatic rollback is attempted.
- `LocalBoundary` retains the original output graph, creates a new copied leaf and resumes prefix backward once. Wrong IDs/shape/dtype, missing or nonfinite gradients terminate that boundary. These local IDs are not the network protocol.
- `snapshot()` and `cpu_state()` are tiny-reference utilities only. Large runtime initialization uses stage construction and one-parameter staging; M4 will implement bounded checkpoint loading.

## Evidence and limitations

The planned Python 3.13 download failed with DNS resolution errors in this execution environment. Supplemental tests used isolated `.venv-local`: cached CPython 3.11.15, PyTorch 2.13.0, macOS 15.5 ARM64. Existing cached distributions were copied/repacked locally without changing their source, then installed offline; global environments and other projects were not modified. The project dependency remains torch 2.11.0, so this supplemental environment intentionally uses `PYTHONPATH=src` rather than pretending to satisfy that pin.

Local supplemental commands (zsh, project root):

```zsh
PYTHONPATH=src PYTORCH_ENABLE_MPS_FALLBACK=0 .venv-local/bin/python -m unittest discover -s tests -v
PYTHONPATH=src .venv-local/bin/python -m hive_train doctor --output artifacts/environment/local.json
PYTHONPATH=src .venv-local/bin/python -m hive_train verify --device cpu --steps 10 --output artifacts/validation/m1-cpu.json
```

Final verification: **19 unittest tests passed** (6.909 s), and the nine-case ten-step CPU reference comparison passed. Independent review identified an interruption-between-updates retry defect, which was fixed and regression-tested; the reviewer confirmed the fix with no remaining blocking finding. CUDA availability was false; MPS was built but availability was false. No GPU execution, local peer networking, capacity benchmark, or distributed recovery was performed. The reference report sets `matches_planned_environment: false`. Local artifact directories are ignored by Git because they contain environment-specific generated evidence; preserve/share reports intentionally when comparing machines.

Recorded artifacts: `artifacts/environment/local.json` and `artifacts/validation/m1-cpu.json`. The supplemental initial fixture SHA-256 is `307033bd5832e24eaac045c9b14cf57a2a618ae3aec45e21ae02f50d377ddcf1`; it is evidence for the recorded torch version, not a promised hash across future RNG implementations. Source/test syntax, package metadata and local documentation links also passed checks.

Next acceptance work: run the same commands on the planned environments on each actual accelerator, compare the fixture hash and recorded semantics, then implement M2 framing/transport/state tests. CPU-only success cannot mark M0/M1 target acceptance complete.
